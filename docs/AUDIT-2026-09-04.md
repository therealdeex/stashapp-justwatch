# Just Watch integration audit — 2026-09-04

The design is a good fit for a television experience: stable channel identities, a wall-clock schedule, one player across channel changes, a unified guide, and desktop channel authoring. The implementation needs another reliability pass before its autosave and programming promises can be trusted. Prioritize lost edits and incorrect lineup membership before adding more networks or visual polish.

Scope: plugin commit `1280fe0`; Android TV commit `f4562be1`. Reviewed the plugin, Channel Studio, Android Just Watch client/schedule/reducer/player integration, and relevant bundled Stash server implementation. No application code or server data was changed. This is a focused integration audit, not a security review of the entire Android app or Stash.

**Verification**

- Plugin: `python3 -m pytest tests/ -q` — **48 passed**.
- Android: Java 21, `./gradlew :app:testDebugUnitTest --tests '*justwatch*' --console=plain` — **103 tests, seven suites, no failures/errors**.
- Read-only requests to the documented PG development server on port 9998: Capabilities, GetCatalog, Directory, FullDirectory, Lineup, and PreviewLineup succeeded. Basic operations took roughly 80–100 ms; FullDirectory roughly 500 ms on this small dataset. These are spot measurements, not performance benchmarks.
- The existing custom channel returned two playable scenes. Preview and TV lineup durations agreed, and their sum matched the rounded health snapshot.
- Isolated Python probes reproduced cookie-auth failure, structural corruption being silently normalized away, seed mutation, and a broken snapshot exception handler. A concurrent save probe reproduced a shared-temp-file collision.
- A Node harness executing the actual extracted autosave callback reproduced loss of the second edit during an in-flight save.
- No device playback, screenshots, or browser interaction session was performed. The attached physical device's server configuration was not established, so it was not used. Codec recovery, remote focus, audio transitions, and long playback sessions still need PG-device verification.

Paths below are relative to the plugin repository unless prefixed `TV/`, which means `/home/shahram/dev/StashAppAndroidTV/`. P1 means fix before relying on the feature; P2 means the next reliability milestone. Proposed acceptance tests are instructions for implementation agents, not claims that those tests currently exist.

**1. P1 — Autosave drops edits made during a save. Owner: Channel Studio agent.**

Evidence: `ui/index.js:966–1004`, particularly the success reload at 978 and follow-up scheduling at 999. An edit made while revision 5 is saving retains revision 5 in `pendingRef`. The first save returns revision 6 and replaces the visible draft. The second save submits its old revision 5, conflicts, and reloads revision 6, discarding the second edit. The Node reproduction produced exactly that sequence. `createChannel` at 1036 independently calls `commitAndReload`, bypassing the serialization guard and creating another race.

Implement one save coordinator for creation, editing, relinking, renumbering, deletion, and settings. Track the acknowledged revision separately from the working draft. After acknowledging a save, retain newer local edits and submit them against the acknowledged revision. On a real external conflict, preserve the draft and offer reload/reapply or a deliberate merge; do not discard it automatically. Never label a newer unsent draft “Saved.”

Acceptance: delay the first response, make a second edit, then finish both requests. Both changes persist without a conflict. Repeat with create during edit, delete during save, failed reload, and a genuine second-tab conflict.

**2. P1 — TV include tags broaden themed channels. Owner: Android filtering agent.**

Evidence: `TV/app/src/main/java/com/github/damontecres/stashapp/ui/pages/justwatch/JustWatchViewModel.kt:814–882`. `mergeTagFilter` replaces the channel's tags with `baseValue + include` using INCLUDES. That is a union. The client then checks only the section include tags, not the original theme. For theme A and section include B, a B-only scene passes even though it does not match A. Filtering after the fixed 50-row fetch can also make a populated channel appear empty or artificially thin.

Express the original source AND section includes AND NOT section excludes using the server's supported nested filter structure. Preserve hierarchy semantics. If some restriction must remain client-side, scan subsequent pages until the playable rotation is filled or the source is exhausted. Keep this logic entirely out of custom plugin channels.

Acceptance: fixtures with A-only, B-only, A+B, and A+B+excluded scenes; only A+B airs. Include a fixture whose first qualifying scene is beyond raw result 50.

**3. P1 — Saved searches lose their text-search constraint. Owner: plugin lineup agent.**

Evidence: `justwatch/lineup.py:32–36,179–189` fetches `find_filter { q }`, then returns only `object_filter`. `fetch_lineup` at 121 constructs a new find filter without `q`. A search-only saved lineup therefore becomes an unrestricted scene filter. A probe with `q: "Bluey"` and an empty object filter confirmed that the outgoing request omitted `q`.

Carry the saved search's membership criteria through both Lineup and PreviewLineup, including text search. Override only pagination and the owner's chosen channel play order. Use the same resolved criteria for health snapshots.

Acceptance: compare source membership with Stash for text-only, object-only, and combined saved searches. Verify changing play order does not change membership.

**4. P1 — Cookie authentication uses the wrong JSON field name. Owner: plugin transport agent.**

Evidence: `justwatch/stash_client.py:82–83` reads `SessionCookie.value`. Stash passes a Go `http.Cookie` with `Name` and `Value`: see `TV/stash-server/pkg/plugin/common/msg.go:18` and its Python example. A realistic cookie envelope produced no Cookie header in the isolated probe. The local install works through its API-key fallback, so successful local requests do not cover stdlib-only cookie authentication.

Read the server's actual `Name`/`Value` fields, optionally accepting lowercase for compatibility. Keep API-key fallback optional as documented. Validate with a realistic raw envelope and no available API-key/config fallback.

Acceptance: an authenticated Lineup request succeeds without PyYAML or an explicitly configured API key. Missing/invalid credentials produce a useful authentication error without exposing secrets.

**5. P1 — Existing catalog corruption can silently erase channels. Owner: plugin storage agent.**

Evidence: `justwatch/catalog.py:52–70,181–210`. Load checks JSON syntax and the top-level object, then normalizes without structural validation. `{"schemaVersion":1,"revision":5,"channels":"broken"}` loads as an empty channel list. Non-dictionary list members are skipped. A later valid save can make that loss permanent. Unsupported schema versions are also replaced with the current version by normalization.

Separate strict stored-catalog parsing from new-draft normalization. Reject unsupported schemas, invalid collection shapes, and invalid channel records with `CatalogError`; preserve the original bytes. Make any repair or migration explicit. Validation must return structured errors for malformed fields rather than crashing inside normalization—for example a numeric name, string source, or null tag list.

Acceptance: malformed-but-valid JSON objects and future schema versions never become empty editable catalogs. Reads and attempted saves preserve the file. Missing files still initialize normally.

**6. P2 — Revision checks and atomic writes are not safe across concurrent processes. Owner: plugin storage agent.**

Evidence: `justwatch/main.py:281–328` checks revision before source-resolution queries, without a lock. `catalog.py:83` uses a shared `catalog.json.tmp`; snapshots use the same fixed-temp-name pattern. Concurrent isolated saves both passed the revision check; one failed with `FileNotFoundError` during rename. Other interleavings can lose a write.

Qualification: Stash's normal job dispatcher serializes tasks (`TV/stash-server/pkg/job/manager.go:130–160`), which protects the ordinary editor route. However, `SYNC_MODES`/`TASK_MODES` are not dispatch enforcement: `_dispatch` accepts their union, and Stash's RunPluginOperation resolver forwards arbitrary arguments directly. Direct invocations can overlap queued tasks. Do not describe the current revision mechanism as generally process-safe.

Use a process-safe catalog lock around the final revision reread/check and write; use unique temporary files on the same filesystem. Snapshot work can follow outside the lock, with revision-aware publication to prevent an older result replacing a newer one. Keep clients using task operations for writes.

Acceptance: simultaneous saves with the same expected revision yield one success and one `revision_conflict`, no lost write, and no temp-file collision.

**7. P2 — Existing channel seeds are mutable through SaveCatalog. Owner: plugin storage agent.**

Evidence: validation checks seed range but never compares it with the persisted channel. In a temporary catalog, changing an existing channel's seed to 123 saved successfully. Omitting it generates a new seed. This violates the documented schedule identity invariant even though the current editor normally preserves it.

Compare existing IDs against the stored catalog and preserve or reject changes to their seed; allocate seeds only for genuinely new channels. A deleted/recreated channel can have a new identity, but ordinary edits must not implicitly reseed it.

Acceptance: changing or omitting a seed on an existing channel cannot alter its stored seed. Renaming, source changes, and number swaps retain identity and seed.

**8. P1 — The editor describes a different rotation from the TV. Owner: shared contract agent.**

Evidence: `TV/.../features/justwatch/JustWatchPluginClient.kt:110–146` requests only page 1 of 50 and treats it as the entire rotation. `justwatch/snapshots.py:115–129` counts the full source and sums up to 20,000 scenes. A 500-scene channel therefore reports a 500-scene loop while the TV repeats at most 50. Dropping scenes without durations after pagination can even make page 1 empty while later pages contain playable scenes.

Choose and document one rotation policy. For the intended authored-library experience, prefer a bounded, versioned rotation assembled server-side, with count, duration, preview, and TV playback derived from that same rotation. If keeping a fixed subset, explicitly distinguish the source library from the active rotation in the editor. Do not fetch an unbounded library on every channel flip.

Acceptance: fixtures with 0, 1, 50, 51, and 500 scenes produce matching scheduled counts and loop lengths on both clients. Include unplayable early results. Repeated retrieval of a rotation version returns the same ordered entries.

**9. P2 — Web tuning settings do not control the TV. Owner: shared settings agent.**

Evidence: `ui/index.js:865–913` says these settings tune the TV's generated channels and offers launch behavior. Android reads local `ServerPreferences`, not plugin catalog settings; its Just Watch AGENTS.md explicitly documents that limitation. The capability response nevertheless advertises `globalSettings: true`. FullDirectory uses plugin thresholds, and the web rail is loaded only once, so even its own displayed automatic lineup can lag a settings edit.

Either connect settings through a versioned, explicit precedence policy, or remove/disable the controls and explain that tuning currently lives on the TV. If server-wide settings are intended, define behavior for multiple TVs and plugin-unavailable fallback. Refresh the directory after effective settings change. Add shared fixture tests for Python/Kotlin automatic tiering, including equal-count ordering and section filters.

Acceptance: a threshold or launch change has the advertised effect on a newly opened TV session. The web and TV directories agree for the same effective configuration.

**10. P2 — Health refresh misclassifies missing sources and breaks on errors. Owner: plugin health agent.**

Evidence: `justwatch/snapshots.py:132` catches `lineup.LookupError`, but that module has no such attribute. A simulated transport failure raised `AttributeError` instead of taking the intended best-effort path. Saved-filter resolution is outside the per-channel try block. Tag/studio/performer existence is never checked here, so deleted entities can appear merely off air rather than needing relink. `sceneCount` counts unplayable scenes as well.

Use the correct exception type, put each channel's resolution/fetch inside its own failure boundary, and distinguish missing source, empty playable rotation, and temporarily unavailable health. Resolve all source types. Derive count and loop duration from the agreed rotation policy. Keep health failures from blocking a committed catalog or preventing other channels' health updates.

Acceptance: deleted tag/studio/performer/filter yields relink; a real empty source yields off air; an outage yields unavailable/stale health. One failing channel does not abort the rest.

**11. P2 — Temporary failures become permanent session-level off-air states. Owner: Android scheduling agent.**

Evidence: `TV/.../ui/pages/justwatch/JustWatchViewModel.kt:467–483` turns non-curated fetch failures into `emptyList()`. `TV/.../features/justwatch/BroadcastSchedule.kt:142` caches that empty timeline for the session with no invalidation. The client also discards Directory/Lineup revisions, and the directory is loaded once, so source edits, paused/deleted channels, and branding changes do not propagate into an open session.

Represent unavailable separately from a successfully empty rotation. Retry transient failures with bounded backoff; do not cache them as emptiness. Use catalog/rotation versions to invalidate changed channels, and refresh at explicit safe boundaries such as foregrounding or a user refresh. Keep a working rotation during a transient outage where practical. Coalesce concurrent loads for the same channel.

Acceptance: fail the first load, restore connectivity, and tune successfully without recreating the feature. Edit/disable a channel while TV is open and verify the agreed refresh policy updates it consistently.

**12. P2 — Save-result polling can hang or miss successful saves. Owner: Channel Studio and transport agents.**

Evidence: `ui/index.js:143–178` polls forever through repeated errors. Every save writes the same `snapshots/save_result.json` (`justwatch/snapshots.py:65–74`). A subsequent tab/task can overwrite a successful request's result before the original tab reads it. Request-ID matching detects a mismatch but cannot recover the missing result. IDs based on time plus a per-tab sequence can also collide across tabs.

Add bounded polling, cancellation, a durable dirty state and a retry action. Store results by an opaque request ID with retention cleanup, or expose a task-result lookup. Use a random UUID and an idempotency policy so an uncertain response can be retried safely. Ensure every handled save failure publishes a correlated result. Coordinate this with item 1.

Acceptance: two tabs save close together and each retrieves its own result; a lost response is recoverable; persistent network failure leaves an actionable state rather than an endless Saving indicator.

**13. P2 — Grouped entity deep links can stall tuning. Owner: Android navigation agent.**

Evidence: `TV/.../ui/pages/justwatch/JustWatchViewModel.kt:1144–1163`. `tune` passes `resolveChannel(channel)` to `tuneInternal` but the schedule lambda still calls `nowPlaying(channel)` on the original entity. State also retains the original key from TuneRequested, so `isChannelStale(resolved)` can immediately reject the result for a grouped entity. Initial launch explicitly accepts entity reverse-index keys, making this path relevant to “Watch as TV.”

Resolve the canonical channel before dispatching the tune state/effect. Use the same key for state, schedule lookup, staleness checks, and guide highlighting.

Acceptance: “Watch as TV” for a solo, grouped, and spillover performer/studio all starts playback on the expected channel with correct highlighting.

**14. P2 — Reserved number collisions appear at larger directory sizes. Owner: shared directory agent.**

Evidence: `TV/.../features/justwatch/ChannelKey.kt:222–262,343–376` allocates 99 ordinal studio/performer numbers while reserving 399/499 for spillover. The 99th ordinary channel therefore collides with spillover. The number-pad lookup special-cases those numbers, so without spillover an ordinary channel displayed as 399/499 can resolve to nothing. `justwatch/autodir.py:_number_rows` repeats the allocation.

Reserve the spillover numbers explicitly and cap ordinary numbered entries at 98, or choose a revised non-overlapping allocation. Apply it consistently to rendering, number-pad lookup, ranges, and the Python mirror.

Acceptance: 98, 99, and 100 ordinary channels, with and without spillover, have unique numbers and every displayed number round-trips to the same channel.

**Television-experience recommendations, after the correctness fixes**

- Keep the single-player approach, wall-clock scheduling, unified guide, and custom-channel isolation. Preserve the deliberate absence of watch-history updates during channel surfing.
- Make one clear LIVE versus time-shift policy. The current app pauses in background and requires Play to resume; next-program skipping can move ahead of live, while end-of-file returns to wall clock. Provide a visible return-to-live action and compute “Up next” from the selected airing when time-shifted. Test the transition at program boundaries.
- Treat active rotations as published versions. A fixed seed and epoch alone do not keep two TVs synchronized if they cached different source contents. Publish changes at a defined boundary and measure tune position after slow scene/stream preparation. Test scenes with multiple files of different durations: the plugin currently uses maximum file duration while the TV's native scene path uses the first file's duration.
- Optimize time to first picture before increasing the automatic catalog. Initial tuning waits for the entire directory, which includes entity queries and studio classification queries. Use a cached directory, prioritize the target channel, and populate remaining sections progressively. Measure cold start, warm flip, fallback-to-transcode, and guide-open latency on the actual TV.
- For sparse libraries, prefer a smaller active dial and an optional way to inspect off-air networks. Repeated filler across many curated channels weakens the feeling of distinct networks. Show a concise channel-unavailable state during recovery without silently making a custom channel air unrelated material.
- Complete keyboard accessibility in Channel Studio: dialog semantics, focus trapping/restoration, Escape dismissal, and accessible names for glyph/color controls. Add recoverable drafts and an explicit retry for autosave failure. Test immediate navigation away after an edit.

**Suggested implementation sequence and release gate**

1. Fix autosave/coordinated creation and result retrieval; protect stored catalogs and stable seeds.
2. Fix membership semantics on both sides and cookie authentication.
3. Agree on rotations and settings ownership; then implement health, invalidation, and recovery against that contract.
4. Fix deep-link and number allocation edge cases; complete PG remote/player testing and startup measurements.

Keep existing contract v1 shapes compatible. Additive fields/operations can remain v1; changing existing response shapes requires a contract bump under the project rules. Share serialized fixtures between Python and Kotlin so tests verify cross-client behavior instead of merely duplicating each implementation's assumptions.

Before calling the integration reliable, run a PG end-to-end matrix: slow autosave with continued typing; two tabs; source deletion/relink; source with more than 50 results; an empty first raw page; network loss/recovery; edits while TV is open; a grouped entity deep link; large number bands; 30 minutes of playback across boundaries; pause/foreground/return-to-live; rapid guide tunes; direct-play and transcode fallback across the available codecs. Do not infer large-library correctness from the small PG library alone—use synthetic fixtures for scale and membership edge cases.
