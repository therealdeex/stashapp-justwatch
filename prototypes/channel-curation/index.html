Channel curation — five working prototypes

The same library — the real 513-network v4-final proposal plus synthetic custom channels and fixture states — driven by five genuinely different workflows. Every variant supports the full review script: search, rename, one-group assignment, rule editing with a plain-language summary, simulated pool/rotation preview, Apply/Discard with durable drafts, bulk moves into new groups, recoverable errors, keyboard operation, and a narrow layout. All counts, previews, schedules and artwork are simulated; no production media or live server calls.

OPTION A

Channel Studio

A searchable dial on the left, a focused editor on the right. Find a channel the way you'd find it on the TV, edit in place, Apply. The classic curation surface — fastest path from "this channel" to "changed".

Group Organizer

Groups first. Pick a group, see its channels as cards, drag or bulk-move between groups, manage the group set itself. Channel editing opens in a drawer so organizing never loses its place. Best for reshaping the lineup's structure.

Open › OPTION C

Channel Library

A dense, sortable, filterable table over all 519 channels with cross-filter multi-select and bulk actions (move / pause / archive) plus CSV definition export. Power-tool territory: maintenance at scale.

Open › OPTION D

Visual Guide

The lineup as it airs: a guide grid with group bands and simulated programs. Click a program for context, edit the channel in a side panel without losing your place. Best for thinking in schedules, not lists.

Open › OPTION E

Guided Curator

One decision at a time: choose a channel, then identity → group → rules → programming, ending in a review that shows the exact before/after before the single Apply. Best for careful edits and creating channels from scratch.

Running the prototypes

  • Start: python3 tools/serve_prototypes.py (repo root) — serves http://localhost:8462/, also published over tailscale at https://dev-lab2.manx-teeth.ts.net:8462/.
  • Restart after reboot: same command. To stop tailscale publishing: tailscale serve --https=8462 off.
  • No build step, no dependencies, no network calls — plain files.

Things to try in every variant

  • Search for a known channel (try / to focus search), then browse by group.
  • Rename it, change its group — watch the unsaved-draft indicator; nothing saves until Apply.
  • Edit rules: ANY/ALL toggles, exclusions, date/duration/recency rows — read the plain-language summary.
  • Compare source pool vs on-air rotation (≤ 50) in the preview — both simulated.
  • Apply (watch progress + acknowledgment) and Discard; switch channels or views with a dirty draft and come back — it's still there.
  • Use Select… / Manage to multi-select channels and move them into a new group with one Apply.
  • Open the Scenario menu (top bar) and try Conflict on Apply, Lost response → retry (retry with Apply — the same request id is reused, nothing duplicates), Validation error, Slow Apply. The draft always survives.
  • Fixture channels: Empty Pool Experiment (#7), Deleted Entity Detector (#8 — edit its source to see the honest error), After Hours (paused), Archive: Late Night Marathons (archived), one 60-char name, and channels with 3,569-performer rule rows (search "Rare Performers" → edit rules → choose performers).
  • Keyboard: Tab/Shift-Tab, Enter/Space to activate, Esc closes dialogs/drawers, arrows move in the guide grid (D).
  • Narrow the window below ~760px — every variant restacks for a small screen.

Reset

  • The Reset button (top bar, every variant) restores the same starting fixture and clears drafts for that variant.
